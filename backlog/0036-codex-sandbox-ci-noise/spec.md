# codex サンドボックス内 CI 実行のノイズ排除

`codex-reviewer` が read-only サンドボックス内で `npm run ci` を回して環境要因の失敗を毎回釈明する無駄を無くす。

## 種別

改善

## 対象

- 場所: `.claude/agents/codex-reviewer.md`、またはレビュー依頼の運用
- 公開面: Verify (外部) のレビュー実行手順

## 背景

この項目は backlog。着手しない。progress は作らない。完了条件は未確定。

`codex-reviewer` が read-only サンドボックスで `npm run ci` を実行すると、`mkdtemp` を使うテストが 90 件失敗する（`EPERM: operation not permitted, mkdtemp '/var/folders/.../T/...'`）。実装の欠陥ではなく環境要因だが、レビュアーが毎回それを切り分けて釈明する必要があり、出力とトークンを無駄にしている。

2026-08-22 のセッションで `0030` と `0033` の両方のレビューで発生し、いずれもレビュアーが「サンドボックス起因であり欠陥ではない」と釈明していた。サンドボックス外では 360〜390 件すべて pass する。

対処の候補:

- (a) エージェント定義に「サンドボックス内で `npm run ci` を回さない。親が実測結果を渡す」と書く
- (b) テスト側が書き込み可能な一時ディレクトリを選べるようにする（ただし `tests/` は凍結対象）
- (c) レビュー依頼時に実測結果を必ず添える運用にする（現状すでにそうしているが、それでもレビュアーが自分で回している）

`0026-review-output-schema`（`task/0026-review-output-schema/spec.md`）と関連する。同じエージェント定義（`.claude/agents/codex-reviewer.md`）を触る可能性があるため、昇格時は 0026 の変更後の定義を前提にする。

## 仕様

変更後に満たしたい振る舞い（検証可能な命題に落とすのは昇格時）。

- `codex-reviewer` のレビュー出力に、サンドボックス起因のテスト失敗の釈明が含まれない
- レビューは親が渡した実測の CI 結果を判定材料にし、サンドボックス内で `npm run ci` を再実行しない（候補 (a) を採る場合）

## 範囲外

- `tests/` 配下のテストコードの変更（凍結対象。候補 (b) を採るなら凍結解除の手続きが要る）
- サンドボックスの権限設定そのものの変更

未確定。候補:

- 親が実測結果を渡さずにレビューを依頼した: レビュアーは承認せず、実測結果を求める
