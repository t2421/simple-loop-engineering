# ID 採番に予約の仕組みを足す

`node tools/start-task.mjs --next-id` が「その時点でコミット済みの最大 ID + 1」を返すだけで予約ができないため、並行起草で同じ ID を掴みうる。採番と確保を安全にする。

## 種別

改善

## 対象

- 場所: `tools/start-task.mjs` の `--next-id`（凍結対象ではない）
- 公開面: CLI。`node tools/start-task.mjs --next-id` の出力と、必要なら新オプション

## 背景

この項目は backlog。着手しない。progress は作らない。完了条件は未確定。

2026-08-22 の backlog リファインメントで実際に発生した。複数エージェントが同一チェックアウト・同一ブランチで並行して起草しており、あるエージェントが `backlog/0036-…/` を未コミットのまま作成中だったため、別のエージェント（spec-author）は `--next-id` の値を信用できず採番を差し戻した。`--next-id` はコミット済みのディレクトリしか見ない（あるいは見る範囲が呼び出し時点のツリーに依存する）ため、未コミットの新規ディレクトリ・並行 worktree・未マージの計画ブランチにある ID と衝突しうる。`task/` と `backlog/` は同じ番号空間なので、衝突すると後からマージする側の付け替えが必要になる。

## 仕様

変更後に満たしたい振る舞い（検証可能な命題に落とすのは昇格時）。

- `--next-id` が、コミット済みに加えて**作業ツリーの未追跡・未コミットの `task/<id>-*` / `backlog/<id>-*`** も走査して最大 ID を求める
- 採番と確保を分けない選択肢も検討する: 例として `--claim <slug>` が ID を計算し、その場で `backlog/<id>-<slug>/`（または `task/`）のディレクトリを作って確保する。確保済みディレクトリは以後の採番から見える
- 並行 worktree（`.worktrees/*`）までは走査しない。そこは docs PR のマージ順で解決する現行規約のまま

## 範囲外

- 番号空間の変更（`task/` と `backlog/` の分離）
- 既存 ID の付け替え

## 失敗時

未確定。候補:

- `--claim` の対象ディレクトリが既に存在する: 何も作らず exit 非 0 で衝突を報告する
