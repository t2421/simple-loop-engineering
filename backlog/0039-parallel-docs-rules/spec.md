# 並行 docs 作業（同一ブランチ）の規約を明文化する

複数エージェントが同一チェックアウト・同一ブランチで docs 作業（backlog リファインメント等)を並行するときの分担と git 操作の規約を CLAUDE.md に足す。

## 種別

その他（ルール変更）

## 対象

- 場所: `CLAUDE.md` の「並列作業（worktree）」節（またはその近傍）
- 公開面: なし（運用規約）

## 背景

この項目は backlog。着手しない。progress は作らない。完了条件は未確定。

CLAUDE.md の「1 worktree = 1 作業 = 1 ブランチ」は実装作業の原則であり、docs 一括作業（backlog リファインメントで複数 ID を同時に触る等）には規約がない。2026-08-22 のリファインメントでは、複数エージェントが `docs/refine-backlog-2` の同一チェックアウトで並行作業し、`git status` に互いの途中状態（未追跡ディレクトリ・部分ステージ）が混ざった。各エージェントには「他の ID に触るな」と口頭で伝えて回避したが、共有インデックスへの並行 `git add` は誤ステージ・誤コミットのリスクが残る。

## 仕様

変更後に満たしたい振る舞い（検証可能な命題に落とすのは昇格時）。

- CLAUDE.md に、同一ブランチでの並行 docs 作業の規約を足す。候補:
  - 親（オーケストレータ）が各エージェントに**触ってよいパス（ID のリスト）を明示的に割り当てる**。割当外のパスは読み書きしない
  - `git add`・`git commit` は**親だけ**が行う。サブエージェントはファイルの作成・編集まで
  - サブエージェントは `git status` 全体を根拠に判断しない（他者の途中状態が混ざる）
- 既存の worktree 原則（実装作業）は変えない

## 範囲外

- ツールによる強制（hook でのパス制限など）。まず規約として明文化する
- 実装作業（コードを触る作業）の並列規約の変更

## 失敗時

なし（運用規約であり、実行時の失敗分岐はない）。
