# 2 番目のプロジェクトへの手移植

ループエンジニアリングの仕組み（`tools/*.mjs`・`CLAUDE.md`・`task/` の構造）を Node 以外の 2 番目のプロジェクトへ**手で**移植し、書き換えが必要だった箇所を記録する。

## 種別

その他（実測・調査。抽象化に先立つ手移植）

## 対象

- 場所: 移植元はこのリポジトリのループ機構全体（`tools/*.mjs`・`CLAUDE.md`・`task/` / `backlog/` の構造・`.github/workflows/`）。移植先は Node 以外の別リポジトリ（Swift か Python。未選定）
- 公開面: なし。成果物は「移植されたプロジェクト」ではなく**書き換え箇所の記録**である

## 背景

ループエンジニアリングの仕組みを他プロジェクトへ持ち出す 3 部作（0042 マニフェスト契約・0043 コア抽出・0044 本候補）のうち、**最初に着手すべき**候補である。番号は 0044 だが、着手順は 0042・0043 より**先**とする。

中心的な主張: **2 つ目のプロジェクトが存在する前に抽象化しない。** 現在の設計は「計算ウェブアプリ 1 件」からの一般化であり、そのまま契約（マニフェスト項目・コアの切り出し線）を決めると speculative generality になる。1 回の手移植のコストは、間違った抽象化を後から剥がすコストよりはるかに小さい。

実測（2026-08-23、`tools/*.mjs` の固有語スキャン。検索語は `npm` / `package.json` / `calc` / `figma` / `playwright` / `cloudflare`）:

- ヒット 0（完全に汎用）: `archive.mjs`、`check-actions.mjs`、`check-progress-coupling.mjs`、`guard-worktree.mjs`
- コメントのみ: `lint-docs.mjs`（1 件）、`stop-hook-ci-dir.mjs`（2 件）
- 1 概念に凝集: `start-task.mjs`（4 件、すべて `npm ci`）、`check-protected-paths.mjs`（8 件、ほぼ `package.json` の scripts 読み取り）
- 真に固有: `run-unit-tests.mjs`（3 件）、`setup-playwright.mjs`（5 件）、`e2e-needed.mjs`（7 件）
- `CLAUDE.md` の固有語: 23 件

この予測（＝書き換えが要るのは上記の固有側だけで、骨格はすでに言語非依存である）が実際に当たるかを、移植で検証するのがこの候補の価値でもある。

## 仕様

手順の骨子:

1. **意図的に Node 以外**のプロジェクト（Swift か Python）を 2 番目の適用先に選ぶ。同じ Node を選ぶと言語結合が露出せず、移植できたように見えてしまう
2. そこへ手で移植する。共通化・自動化はしない
3. **書き換えた箇所を 1 件ずつ記録する。** ファイル・行相当の粒度で「何を」「何に」「なぜ」を残す。この記録が 0042 のマニフェスト項目の原資料になる

移植で特に観察し、記録に含める点:

- `check-protected-paths.mjs` の「検証コマンドの定義がどのファイルにあるか」（Node では `package.json` の scripts）が、移植先で何に相当するか（`Makefile` / `pyproject.toml` / `build.gradle` / `Package.swift`）
- `start-task.mjs` の依存導入コマンド（`npm ci`）の対応物
- `run-unit-tests.mjs` のテスト列挙が、移植先の慣習でそもそも必要か（多くの言語ではテストランナーが自前で発見する）
- e2e・見た目の工程が移植先に**存在しない**場合、ループが破綻せず省略できるか
- `CLAUDE.md` のどの記述が書き換え不要（不変の原則）で、どこが穴（プロジェクト固有）だったか

記録は、背景の実測（汎用 / コメントのみ / 1 概念に凝集 / 真に固有）の分類と突き合わせ、予測が当たった箇所・外れた箇所を明示する。

**未解決の点**: 移植先プロジェクトの選定自体が未確定である（Swift か Python か、既存リポジトリか新規か）。昇格時に決める。

## 範囲外

- 抽象化・共通化の設計と実装（0042 マニフェスト契約・0043 コア抽出でやる）
- 移植ツール・スクリプトの作成（手移植が前提。自動化しない）
- Node 製プロジェクトへの移植（言語結合が露出しないため対象外）
- 移植先プロジェクトのアプリケーション機能そのものの開発
- このリポジトリ側の `tools/*.mjs`・`CLAUDE.md` の書き換え

## 失敗時

なし。
