# アーカイブ手順の自動化

PR マージ後のアーカイブ（Status 更新・ファイル移動・パス書き換え）を 1 コマンドで実行できるようにする。

## 種別

機能追加

## 対象

- 場所: `tools/archive.mjs`
- 公開面: `node tools/archive.mjs <作業名>`（例: `node tools/archive.mjs calc-page`）

## 背景

アーカイブは「Status を Done に → spec を `specs/archive/` へ → progress と抽出物を `progress/archive/` へ → Target Spec のパスを直す」の 4 手順を手作業で行っており、漏れやすい。Loop Engineering の Automations 要素の最小の題材として、この定型処理をスクリプト化する。起動は人間またはエージェントが行う（定期実行は範囲外）。

## 仕様

`node tools/archive.mjs <作業名>` は次を行う。

1. `progress/<作業名>.md` の **PR** に URL があり、その PR が `gh pr view` でマージ済みであることを確認する
2. 進捗の **Status** を `Done` にする
3. `specs/<作業名>.md` を `specs/archive/` へ移動する
4. `progress/<作業名>.md` と、同じベース名の抽出物（`<作業名>.figma.json`、`<作業名>.png` など）を `progress/archive/` へ移動する
5. 移動後の進捗の **Target Spec** を `specs/archive/<作業名>.md` に書き換える

条件を満たさない場合はファイルを一切変更せず、終了コード非 0 で理由を表示する。移動ロジックは PR 確認部と分離し、ユニットテスト可能にする。

## 範囲外

- マージの自動検知（cron・GitHub Actions 等による無人起動）
- PR の作成・マージ自体の自動化
- `TEMPLATE.md` の移動（対象外として拒否する）

## 失敗時

- **PR** が `未作成`、または PR が未マージ: 何も変更せず失敗する
- `specs/<作業名>.md` または `progress/<作業名>.md` が存在しない: 何も変更せず失敗する
- 作業名に `TEMPLATE` を指定: 何も変更せず失敗する

## 例

| 操作または入力 | 期待結果 |
|---|---|
| マージ済み PR を持つ作業名で実行 | Status が `Done`、spec / progress / 抽出物が `archive/` へ移動、Target Spec がアーカイブ後のパスになる |
| PR 未マージの作業名で実行 | 変更なし、終了コード非 0 |
| 存在しない作業名で実行 | 変更なし、終了コード非 0 |
| `TEMPLATE` を指定して実行 | 変更なし、終了コード非 0 |

## 完了条件

次をすべて満たしたとき、この仕様は完了とする。検証はこれらの条件に対して行い、テスト実行結果などのコマンド出力を根拠にする。

1. 「対象」が仕様どおりに公開または修正されている。
2. 「例」がすべて、テストまたは再現手順で同じ結果になる。
3. 「失敗時」に書いた入力・操作で、仕様どおり失敗する。該当がなければこの項は「なし」。
4. 「範囲外」を実装していない。
5. 移動・書き換えロジックが `tests/` のユニットテスト（一時ディレクトリ上で実行、PR 確認は注入可能にしてモック）で「例」を網羅している。
