# アーカイブ時の PR 帰属の検証

`tools/archive.mjs` が、進捗の **PR** 欄の URL がこのリポジトリのこの作業の PR であることを確かめるようにする。

## 種別

改善

## 対象

- 場所: `tools/archive.mjs`
- 公開面: `node tools/archive.mjs <作業名>`（成功条件が厳しくなる。使い方は変わらない）

## 背景

現在の `checkPrWithGh` は `gh pr view <url> --json state` の結果しか見ない。`MERGED` でありさえすれば通るため、次が素通りする。

- 進捗の **PR** 欄に、**別リポジトリ**のマージ済み PR の URL が書いてある
- 進捗の **PR** 欄に、**同じリポジトリの別作業**のマージ済み PR の URL が書いてある

いずれの場合も、その作業の実装 PR が未マージのままアーカイブされる。アーカイブは「実装が main に入った」ことの記録なので、これは記録の嘘になる。

`specs/archive/archive-automation.md` のレビューで指摘されたが、同 spec の「仕様」が `gh pr view` でのマージ確認しか要求していなかったため、範囲外として見送った経緯がある（`progress/archive/archive-automation.md` の 12:00）。

## 仕様

`archive(name)` は、PR がマージ済みであることに加えて次を確かめる。満たさなければ**ファイルを一切変更せず**、終了コード非 0 で理由を表示する。

- PR の URL が、実行中のリポジトリの PR である。`gh repo view --json nameWithOwner` と、URL から取れる `owner/repo` が一致すること
- PR の head ブランチが、進捗の **Branch** と一致すること。進捗に **Branch** が無い、または PR の head ブランチが取得できない場合は失敗とする

判定はマージ確認と同じく注入可能にし、`gh` を呼ばずにテストできるようにする。

## 範囲外

- PR の内容（差分）がその作業のものであるかの検証
- `gh` 以外の経路（GitHub API 直叩き）への切り替え
- 進捗の **Branch** 欄の書式の変更

## 失敗時

- URL のリポジトリが実行中のリポジトリと異なる: 何も変更せず失敗する
- PR の head ブランチが進捗の **Branch** と異なる: 何も変更せず失敗する
- 進捗に **Branch** 欄が無い: 何も変更せず失敗する
- `gh repo view` が失敗する（リモート未設定など）: 何も変更せず失敗する。素通りさせない

## 例

| 操作または入力 | 期待結果 |
|---|---|
| このリポジトリの、その作業の head ブランチのマージ済み PR | アーカイブされる |
| 別リポジトリのマージ済み PR の URL | 変更なし、終了コード非 0 |
| 同じリポジトリだが別ブランチのマージ済み PR の URL | 変更なし、終了コード非 0 |
| 進捗に **Branch** 欄が無い | 変更なし、終了コード非 0 |
| `gh repo view` が失敗する | 変更なし、終了コード非 0 |

## 完了条件

次をすべて満たしたとき、この仕様は完了とする。検証はこれらの条件に対して行い、テスト実行結果などのコマンド出力を根拠にする。

1. 「対象」が仕様どおりに公開または修正されている。
2. 「例」がすべて、テストまたは再現手順で同じ結果になる。
3. 「失敗時」に書いた入力・操作で、仕様どおり失敗する。該当がなければこの項は「なし」。
4. 「範囲外」を実装していない。
5. 帰属の判定が `tests/` のユニットテスト（`gh` を注入で差し替え）で「例」の各行を網羅している。既存のアーカイブ動作（正当な作業のアーカイブ）が変更前と同じく成功する。
