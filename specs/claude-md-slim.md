# CLAUDE.md の整理と方針追記

CLAUDE.md の二重管理・重複を削り、手順知識を Skill に切り出し、トークンコスト方針を追記する。

## 種別

改善

## 対象

- 場所: `CLAUDE.md`、`.claude/skills/figma-extract/SKILL.md`（新規）
- 公開面: なし（エージェント向けドキュメント）

## 背景

- 「状態」節が個別作業の一覧をハードコードしており、`progress/` と二重管理でドリフトする（実際に作業のたびに手動更新が発生している）
- Figma 抽出手順・見た目テストの知識が CLAUDE.md に集中し、毎セッション全ロードされる。Loop Engineering の Skills 要素（再利用知識の切り出し）が未体験
- 記事が警告するトークンコストへの方針が無い
- 「進捗」節が `progress/TEMPLATE.md` の内容をほぼ再掲している

## 仕様

- 「状態」節から個別作業の列挙（「現在の作業:」以下）を削除し、「`progress/` の `archive/` 以外が未完了の作業」というルールだけを残す
- Figma 抽出の手順（使うツール、抽出対象プロパティ、保存先の規約）を `.claude/skills/figma-extract/SKILL.md` に切り出し、CLAUDE.md の「見た目」節からは参照のみとする
- 「トークンコスト」の節を追加する。最低限次を含む: レビューサブエージェントへ渡すのは差分と対象 spec のみ / レビュー往復の上限は既存の 5 回 / 役割ごとにモデルを変える場合はエージェント定義に書く
- 「進捗」節のうち `progress/TEMPLATE.md` と重複する記述を削り、テンプレへの参照に置き換える
- 開発ループの工程（Plan〜Archive）と「変えてはいけないもの」は変更しない

## 範囲外

- `specs/TEMPLATE.md` / `progress/TEMPLATE.md` の変更
- 開発ループの工程の追加・削除
- figma-extract 以外の Skill の新設

## 失敗時

なし。

## 例

| 操作または入力 | 期待結果 |
|---|---|
| CLAUDE.md を「現在の作業:」で検索 | 一致なし |
| `.claude/skills/figma-extract/SKILL.md` を開く | Figma 抽出手順が存在し、CLAUDE.md から参照されている |
| CLAUDE.md を「トークン」で検索 | トークンコスト方針の節が存在する |

## 完了条件

次をすべて満たしたとき、この仕様は完了とする。検証はこれらの条件に対して行い、テスト実行結果などのコマンド出力を根拠にする。

1. 「対象」が仕様どおりに公開または修正されている。
2. 「例」がすべて、テストまたは再現手順で同じ結果になる。
3. 「失敗時」に書いた入力・操作で、仕様どおり失敗する。該当がなければこの項は「なし」。
4. 「範囲外」を実装していない。
5. `npm run ci` が変更前と同じく成功する（ドキュメント変更が検証を壊していない）。「例」の検索結果（grep 出力）を会話に貼る。
