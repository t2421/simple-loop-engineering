# 凍結ファイルの改訂手続き

「変えてはいけないもの」の正規の改訂手続きを定義し、初適用としてテスト内の環境セットアップコードを退避する。

## 種別

改善

## 対象

- 場所: `CLAUDE.md`（「変えてはいけないもの」節）、`tools/setup-playwright.mjs`（新規）、`tests/calc-page.test.mjs`（セットアップ分岐の削除）、`package.json`（`pretest` の追加）
- 公開面: `npm run ci`（挙動は不変。素の checkout で `npm ci && npm run ci` が通ることも不変）

## 背景

凍結が絶対のため、calc-page 作業で Chromium の自己インストール分岐がテストコード内に実装された（試行ログ 16:30 以降）。凍結の目的は「検証を弱める変更」の防止であり、検証を強める・環境を整える変更まで塞ぐのは過剰。改訂の正規ルートを定義し、その初適用でテストコードから環境セットアップを分離する。

この spec 自体が、手続きの求める「改訂内容の spec 化」に当たる。`specs/guard-protected-paths.md` のガード導入後は `allow-protected-change` ラベルで通す。

## 仕様

- CLAUDE.md「変えてはいけないもの」に改訂手続きを追記する: 凍結対象の変更は、(1) 変更内容と理由を spec に書き、(2) その PR を人間がマージした場合のみ許される。エージェントが自らの判断で凍結対象を書き換えることは引き続き禁止
- 手続きの初適用として:
  - `tests/calc-page.test.mjs` 内の Chromium 自己インストール分岐（`npx playwright install chromium` の実行とリトライ）を `tools/setup-playwright.mjs` へ移す
  - `package.json` に `"pretest": "node tools/setup-playwright.mjs"` を追加する（`test` / `ci` は変更しない）
  - テストの検証内容（アサーション・期待値・件数）は変更しない

## 範囲外

- 上記以外の凍結ファイルの変更
- CI ワークフローの変更（Ubuntu ランナー向け `--with-deps` の明示ステップは現状維持）

## 失敗時

- Chromium が未導入の環境で `npm test`: `pretest` が導入を行い、テストは成功する。導入自体が失敗した場合はエラーを表示して失敗する（無言でスキップしない）

## 例

| 操作または入力 | 期待結果 |
|---|---|
| 素の checkout で `npm ci && npm run ci` | 43/43 pass（セットアップは `pretest` が担う） |
| `tests/calc-page.test.mjs` を `playwright install` で検索 | 一致なし |
| CLAUDE.md を「改訂」で検索 | 凍結ファイルの改訂手続きが存在する |

## 完了条件

次をすべて満たしたとき、この仕様は完了とする。検証はこれらの条件に対して行い、テスト実行結果などのコマンド出力を根拠にする。

1. 「対象」が仕様どおりに公開または修正されている。
2. 「例」がすべて、テストまたは再現手順で同じ結果になる。
3. 「失敗時」に書いた入力・操作で、仕様どおり失敗する。該当がなければこの項は「なし」。
4. 「範囲外」を実装していない。
5. `npm run ci` のテスト件数と結果が変更前と一致する（検証内容を変えていない根拠として出力を会話に貼る）。
