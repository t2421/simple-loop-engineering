# ループエンジニアリング 50分ハンズオン

**必要なもの: Node.js と Claude Code だけ。`npm install` は一度もしません。**

やることは1つです。**壊れたTodoを、ループで直す。**
そのために5回ループを回しますが、**最初の4回はわざと失敗させます。**
失敗を自分の目で見るのが目的で、成功例をなぞっても身につかないからです。

| STEP | 時間 | やること | 得られるもの |
|---|---|---|---|
| 0 | 5分 | 準備 | 壊れた状態の確認 |
| 1 | 10分 | **わざと騙される** | 評価役はツールを実行しない、を体感する |
| 2 | 10分 | 条件を直す | 「出力を貼らせる」の効果 |
| 3 | 10分 | **わざとズルされる** | 不変条件がなぜ要るか |
| 4 | 10分 | UIの条件を書く | 「アクセシブル」を件数に翻訳する |
| 5 | 5分 | **わざと止める** | 載せない判断 |

---

## STEP 0 — 準備（5分）

### やること

`starter/` の4ファイルを新しいフォルダにコピーして、Claude Code を起動します。

```bash
cp -r starter loop-todo && cd loop-todo
git init && git add -A && git commit -m "init"
claude
```

`git init` は STEP 3 で使います。忘れずに。

### 壊れている状態を確認する

```bash
node --test todo.test.mjs
```

こう出ます。

```
# pass 3
# fail 3
```

`toggle` が2回押しても戻らない、`remove` が未実装、の2つが原因です。
**この「3 fail」を0にするのが、これから回すループの仕事です。**

### ✅ 確認
- `node --test todo.test.mjs` で `fail 3` が出た
- `echo $?` が `1` を返す（← 終了コードが停止条件に使えるということ）

## STEP 1 — わざと騙される（10分）

> **狙い: 一番よくある失敗を、最初に自分で踏む。**

### やること

Claude Code に**そのまま**貼ってください。

```
/goal テストが全部通るようにして
```

### 見るべきもの

おそらく**1〜2ターンで「達成」になります。** そうなったら、ターミナルで確認してください。

```bash
node --test todo.test.mjs
```

**まだ fail が残っていることがあります。** あるいは通っていても、
「通りました」という報告だけで達成判定が出ているはずです。

### なぜこうなるのか

`/goal` の評価役は**会話に出た内容だけを読みます。コマンドは実行しません。**
だから「テストは全部通りました」と実装役が書けば、それが判定材料になります。
テストを実際に走らせたかどうかを、評価役は知る手段がありません。

### 学んだこと

> 停止条件に「何が満たされるか」だけ書くと、**自己申告で満たせてしまう。**

```bash
/goal clear
```

## STEP 2 — 条件を直す（10分）

> **狙い: 「証明の手段」を条件に足すと何が変わるか見る。**

### やること

差分は一箇所だけです。**「出力を会話に貼ること」を足します。**

```
/goal node --test todo.test.mjs を実行し、その出力全文を会話に貼ること。
fail 0 であること。10ターンで止めること。
```

### 見るべきもの

**却下理由を毎ターン読んでください（Ctrl+O）。**

STEP 1 では「達成」で終わっていたのが、今度は

```
まだ fail 2 が残っている
```

のように、**具体的な数字で却下されます。** そしてその却下理由が、
次のターンの実装役への指示として機能します。これが正常に回っているループの姿です。

### ✅ 確認
- 却下理由に**数字**が出ている
- 最終的に `fail 0` の**実際の出力**が会話にある
- 自分のターミナルでも `node --test todo.test.mjs` が通る

### 学んだこと

> 条件は「測れる終了状態」＋「**どうやってそれを会話に出すか**」で1セット。

---

## STEP 3 — わざとズルされる（10分）

> **狙い: 条件は満たせるが、目的は達成されない状態を見る。**

### やること

一度戻して、意地悪な指示を混ぜます。

```bash
git checkout todo.mjs todo.test.mjs
```

```
/goal node --test todo.test.mjs を実行し出力を貼ること。fail 0 であること。
どんな手段を使ってもよい。10ターンで止めること。
```

### 見るべきもの

「どんな手段を使ってもよい」があると、**テストの方を書き換えて `fail 0` にする**
可能性があります。そうなったか確認してください。

```bash
git diff --stat
```

`todo.test.mjs` が変更されていたら、**条件は満たされたのに目的は1ミリも達成されていません。**

### 直し方

**変えてはいけないものを条件に書きます。**

```
/goal node --test todo.test.mjs を実行し出力を貼ること。fail 0 であること。
todo.test.mjs は変更しないこと。git diff --stat の出力を貼って証明すること。
10ターンで止めること。
```

### 学んだこと

> 停止条件には**不変条件**が要る。
> テストや期待値を書き換えられるなら、大抵の条件は「達成」できてしまう。

## STEP 4 — UIの条件を書く（10分）

> **狙い: フロントエンド特有の「言葉でしか言えない品質」を、件数に翻訳する。**

`index.html` には、わざと2種類の問題を入れてあります。

- `div` に `onclick` を付けている（キーボードで操作できない）
- 色を CSS 変数を使わず直接書いている

### まず測る

```bash
node check.mjs
```

```
check: problems 8
```

**「アクセシブルにして」は条件になりませんが、「problems 0」は条件になります。**
これが翻訳です。`check.mjs` は依存ゼロの30行程度のスクリプトなので、
中を読めば「何を測っているか」がすぐ分かります。

### やること

```
/goal node check.mjs を実行し出力を貼ること。problems 0 であること。
かつ node --test todo.test.mjs も fail 0 のままであること（出力を貼ること）。
check.mjs と todo.test.mjs は変更しないこと。15ターンで止めること。
```

`check.mjs` を不変条件に入れるのを忘れないでください。
入れないと、**チェッカーの方を緩めて 0 にできます。**

### ✅ 確認
- `problems 0` の実際の出力が会話にある
- `git diff --stat` に `check.mjs` が出ていない
- ブラウザで開いて、Tabキーだけで完了・削除ができる

```bash
python3 -m http.server 8000   # ブラウザで localhost:8000
```

### 学んだこと

> 「アクセシブル」「崩れていない」「速い」は、**すべて件数か数値に翻訳できる。**
> 翻訳した瞬間に、ループに載る。

---

## STEP 5 — わざと止める（5分）

> **狙い: 載せない判断を、実際にやってみる。**

### やること

```
/goal このTodoアプリを、ユーザーが直感的に使えるようにして
```

### 見るべきもの

**何ターン回っても終わりません。** あるいは根拠なく「達成」します。
どちらにしても、却下理由は具体的になりません。3ターンほど見たら止めてください。

```bash
/goal clear
```

### なぜか

「直感的」には終了状態がありません。件数にも終了コードにも翻訳できない。
**これは条件の書き方が下手なのではなく、ループに載せる仕事ではありません。**

### 学んだこと

> 停止条件が書けないときは、たいてい**自分がまだ「何ができたら完成か」を決めていない。**
> それはエージェントの問題ではなく仕様の問題で、ループは肩代わりしてくれない。

## まとめ — 停止条件の型

50分で触ったことは、結局この3行に集約されます。

```
(1) 測れる終了状態   … fail 0 / problems 0 / exit 0
(2) 証明の手段       … そのコマンドを実行し、出力を会話に貼ること
(3) 不変条件         … テストとチェッカーは変更しないこと
                     ＋ Nターンで止めること
```

書けなければ、載せない。

### 次にやること

自分のプロジェクトの直近のタスクを1つ選び、この3行の型で条件を書いてみてください。
**書けなかったタスクが出てきたら、それが今回一番の収穫です。**
