# 並行 docs 作業（同一ブランチ）の規約を明文化する

複数エージェントが同一チェックアウト・同一ブランチで docs 作業（backlog リファインメント等)を並行するときの分担と git 操作の規約を CLAUDE.md に足す。

## 種別

その他（ルール変更）

## 対象

- 場所: `CLAUDE.md` の「並列作業（worktree）」節（またはその近傍）
- 公開面: なし（運用規約）

## 背景

CLAUDE.md の「1 worktree = 1 作業 = 1 ブランチ」は実装作業の原則であり、docs 一括作業（backlog リファインメントで複数 ID を同時に触る等）には規約がない。2026-08-22 のリファインメントでは、複数エージェントが `docs/refine-backlog-2` の同一チェックアウトで並行作業し、`git status` に互いの途中状態（未追跡ディレクトリ・部分ステージ）が混ざった。各エージェントには「他の ID に触るな」と口頭で伝えて回避したが、共有インデックスへの並行 `git add` は誤ステージ・誤コミットのリスクが残る。

2026-08-23 のリファインメントで現存を確認した（CLAUDE.md に同一ブランチ並行 docs 作業の規約は無い）。

2026-08-24 のセッションで、この規約案を実際に適用した。backlog 6 件の昇格作業で、親（オーケストレータ）が 6 つの spec-author サブエージェントを同一チェックアウト・同一ブランチ（`docs/promote-backlog`）で並行実行し、次の分担を明示的に指示した。

- 各エージェントに担当ディレクトリを 1 つだけ割り当て、割当外のファイルは変更しない
- `git add` / `git commit` / `git mv` は親だけが行う。サブエージェントはファイルの作成・編集まで
- サブエージェントは `git status` 全体を根拠に判断しない

これは本仕様の「仕様」に挙げた規約そのものであり、実運用で機能した実例である。

## 仕様

- CLAUDE.md の「並列作業（worktree）」節（またはその近傍）に、同一チェックアウト・同一ブランチでの並行 docs 作業の規約として次の 3 項目を足す
  - 親（オーケストレータ）が各エージェントに**触ってよいパス（担当ディレクトリ・ID のリスト）を明示的に割り当てる**。割当外のパスは変更しない
  - `git add`・`git commit`・`git mv` は**親だけ**が行う。サブエージェントはファイルの作成・編集まで
  - サブエージェントは `git status` 全体を根拠に判断しない（他者の途中状態が混ざる）
- 既存の worktree 原則（実装作業の「1 worktree = 1 作業 = 1 ブランチ」）は変えない
- この変更は CLAUDE.md へのルール変更なので、「コミットとマージ」の規約どおり**独立した docs PR** で main へ入れる。進行中の作業ブランチに混ぜない

## 範囲外

- ツールによる強制（hook でのパス制限など）。まず規約として明文化する
- 実装作業（コードを触る作業）の並列規約の変更

## 失敗時

なし（運用規約であり、実行時の失敗分岐はない）。

## 例

| 操作または入力 | 期待結果 |
|---|---|
| CLAUDE.md の「並列作業（worktree）」節（またはその近傍）を読む | 同一ブランチ並行 docs 作業の規約として、パス割当（親が担当を明示的に割り当て、割当外は変更しない）・git 操作（`add` / `commit` / `mv`）は親のみ・`git status` 全体を根拠に判断しない、の 3 項目がすべて明記されている |
| `grep -n "1 worktree = 1 作業 = 1 ブランチ" CLAUDE.md` | 変更前と同じ行がヒットする（実装作業の worktree 原則は無変更） |

次をすべて満たしたとき、この仕様は完了とする。検証はこれらの条件に対して行い、テスト実行結果などのコマンド出力を根拠にする。

1. 「対象」が仕様どおりに公開または修正されている。
2. 「例」がすべて、テストまたは再現手順で同じ結果になる。
3. 「失敗時」に書いた入力・操作で、仕様どおり失敗する。該当がなければこの項は「なし」。
4. 「範囲外」を実装していない。
5. CLAUDE.md の「並列作業（worktree）」節（またはその近傍）に、同一チェックアウト・同一ブランチでの並行 docs 作業の規約として次の 3 項目がすべて明記されている。
   - 親（オーケストレータ）が各エージェントに触ってよいパス（担当ディレクトリ）を明示的に割り当て、サブエージェントは割当外のパスを変更しないこと
   - `git add`・`git commit`・`git mv` は親だけが行い、サブエージェントはファイルの作成・編集までとすること
   - サブエージェントは `git status` 全体を根拠に判断しないこと
6. `git diff` で、CLAUDE.md の「1 worktree = 1 作業 = 1 ブランチ」を含む既存の worktree 原則の記述に変更がない。
7. この変更を main へ入れる PR の差分が、CLAUDE.md と `task/0039-parallel-docs-rules/progress.md` の更新だけである（独立した docs PR。進行中の作業ブランチに混ぜない）。
