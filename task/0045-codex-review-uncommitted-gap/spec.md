# `codex review --uncommitted` の取りこぼし

レビュー起動時に実装差分が未コミットでない場合、`codex review --uncommitted` が実装を見ずに空の差分をレビューしてしまう経路をふさぐ。

## 種別

バグ修正

## 対象

- 場所: `.claude/agents/codex-reviewer.md` の「手順」節（レビュー起動コマンドと、差分 0 件／base 解決失敗の扱い）
- 公開面: Verify (外部) でレビュアーが実際に読む差分の範囲

## 背景

`.claude/agents/codex-reviewer.md` は `codex review --uncommitted` でレビューを起動する。この形は「実装がまだコミットされていない」ことを前提にしている。

ところが開発ループの実際の進み方では、実装を先にコミットしてから進捗を更新することがある。0036 では実装（`244a4c9`）をコミットした後に進捗の更新（`2d11992`・`3d9c967`）を重ねた。この状態で `--uncommitted` を起動すると、拾えるのは未コミットの差分だけであり、**レビュー対象であるはずの実装差分がゼロ件になる。**

空の差分に対するレビューは指摘を返さない。つまり **Critical ゼロという結果が、検証したから出たのか、何も見なかったから出たのかを区別できない。** これは「Critical がゼロになるまで繰り返す」という停止条件を、検証せずに満たせてしまう経路である。

現行の「手順」はフェンス内の既定起動を `codex review --uncommitted` とし、「ブランチが分かれていて未コミットが無いときは `codex review --base main`」と但し書きしている。実装がコミット済みで進捗だけ未コミットのときは未コミットが「無い」ではないため、但し書きは発火せず、この穴を塞がない。

0036 の過程で見つかったが、0036 の spec が「既存の手順は変えない」としていたため範囲外として残した。0047（アーカイブ済み）が `tests/agent-defs.test.mjs` で、同ファイルのサンドボックス再実行禁止・実測 CI 必須・出力スキーマ 4 項目の順を恒久検証している。この作業は「手順」の起動を直すが、その 3 事実は残す。

## 仕様

レビュアーが読む差分は、**その作業ブランチが main から分岐して以降の全変更**でなければならない。未コミットかどうかで範囲が変わってはいけない。

起動方法（昇格時に確定）:

- 既定の起動は `codex review --base main`（または、作業ブランチが main から分岐して以降のコミット済み変更と未コミット変更の両方を含む同等）
- `--uncommitted` だけを既定起動にしてはいけない。`--uncommitted` 単独では、実装がコミット済みのときに実装差分を読まない
- `codex review --base main` が未コミットを含まないなら、手順はコミット済み（vs main）に加えて未コミットも読む。未コミットだけを見て実装を飛ばしてはいけない
- `--uncommitted` をフォールバックとして残すなら、作業ブランチに main からのコミットがありワーキングツリーがクリーンなときに黙ってそれを走らせてはいけない

差分 0 件と「指摘無し」の区別:

- 解決した差分が 0 件のとき、レビュアーは承認しない。差分が取れない／空であることを理由として報告する
- 「差分を見たうえで指摘が無い」と「差分を見ていない（空／取得失敗）」を、レビュー結果の書式の上で区別できるようにする。後者を Critical ゼロとして扱わない

0047 が固定した次の 3 事実は残す（手順の文言を変えてよいが、事実を消してはいけない）:

1. サンドボックス内での `npm run ci`・ユニットテスト・e2e 再実行を禁じる
2. 親が実測の CI 結果を渡していないときは承認しない
3. 出力スキーマの必須 4 項目名がこの順: `severity`、`根拠`、`完了条件番号`、`一文の要約`

## 範囲外

- codex 本体の挙動そのものへの変更
- レビューの判定基準（Critical / High / Medium / Low の対応づけ）の変更
- 出力スキーマの項目名・順番の変更（0047 が `tests/agent-defs.test.mjs` で恒久検証している）
- サンドボックス再実行禁止・実測 CI 必須の削除または骨抜き

## 失敗時

- 解決した差分が 0 件: 承認せず、差分が取れない／空である旨を報告する。「指摘が無い」とは書かない
- base（main）の解決に失敗: 黙って `--uncommitted` にフォールバックせず、明示的に失敗して承認しない
- `--uncommitted` をフォールバックとして残す場合に、作業ブランチに main からのコミットがありワーキングツリーがクリーン: `--uncommitted` を黙って走らせない（既定の `--base main` または同等を使う。それが失敗したら上の「base の解決に失敗」と同じ）

## 例

検証に使う具体例。1〜4 行目は定義ファイルの内容で機械的に確認する。5〜7 行目はエージェントの振る舞いのため非決定的であり、再現手順としての補助的な確認とする。

| 操作または入力 | 期待結果 |
|---|---|
| `grep -n "codex review --base main" .claude/agents/codex-reviewer.md` | 「手順」の既定起動（または committed+uncommitted vs main を含む同等の説明）としてヒットする |
| `grep -n "codex review --uncommitted" .claude/agents/codex-reviewer.md` | ヒットしても、作業ブランチに main からのコミットがあるときの既定起動としては書かれていない。フォールバックなら、クリーンツリー＋コミットありで黙って走らせない条件が同じ節にある |
| `grep -n "承認しない" .claude/agents/codex-reviewer.md` | 差分 0 件（取れない／空）のとき承認しない旨の行が「手順」またはそれに続く規則としてある |
| `node --test tests/agent-defs.test.mjs` | pass（0047 の 3 事実: サンドボックス再実行禁止、実測 CI 必須、スキーマ 4 項目の順が残る） |
| 実装をコミット済み・進捗だけ未コミットの作業ブランチでレビューを起動 | `codex review --base main`（または同等）が使われ、main からの実装差分がレビュー対象になる。`--uncommitted` だけは走らず、実装 0 件にはならない |
| 実装をコミット済み・ワーキングツリーがクリーンな作業ブランチでレビューを起動 | 同上。`--uncommitted` を黙って走らせない |
| 解決した差分が 0 件、または `codex review --base main` の base 解決に失敗 | 承認しない。差分が取れない／空、または base 解決失敗を報告する。「指摘ゼロ」とは書かない。後者では黙って `--uncommitted` にフォールバックしない |

## 完了条件

次をすべて満たしたとき、この仕様は完了とする。検証はこれらの条件に対して行い、テスト実行結果などのコマンド出力を根拠にする。

1. 「対象」が仕様どおりに公開または修正されている。
2. 「例」がすべて、テストまたは再現手順で同じ結果になる。
3. 「失敗時」に書いた入力・操作で、仕様どおり失敗する。該当がなければこの項は「なし」。
4. 「範囲外」を実装していない。
5. `.claude/agents/codex-reviewer.md` の「手順」が、作業ブランチが main から分岐して以降の全変更（コミット済み・未コミットを問わない）を読む起動になっている。既定は `codex review --base main`（または committed+uncommitted vs main を含む同等）であり、`codex review --uncommitted` だけを既定起動にしていない。`grep -n "codex review --base main"` の出力で該当行を提示できる。
6. 同ファイルに、解決した差分が 0 件のとき承認せず、差分が取れない／空である旨を報告する規則がある。「差分を見たうえで指摘が無い」と「差分を見ていない（空／取得失敗）」を書式上区別する旨がある。`grep` の出力で該当行を提示できる。
7. 同ファイルに、base（main）の解決に失敗したとき黙って `--uncommitted` へフォールバックせず明示的に失敗する規則がある。`--uncommitted` をフォールバックとして残すなら、作業ブランチに main からのコミットがありワーキングツリーがクリーンなときに黙って走らせないことが同じ節に書いてある。`grep` の出力で該当行を提示できる。
8. 出力スキーマの必須 4 項目名と順番（`severity` → `根拠` → `完了条件番号` → `一文の要約`）を変えていない。サンドボックス内再実行禁止と、親が実測 CI を渡していないときは承認しない、の 2 事実も残っている。`node --test tests/agent-defs.test.mjs` が pass することで検証する。
9. 実装差分は `.claude/agents/codex-reviewer.md` の「手順」（と、置くなら新規の小さなテスト）に限る。`codex` 本体・severity 対応づけ・出力スキーマの項目名・順番・`loop-core/`・`package.json`・凍結リストを変えていないことを `git diff main --stat` で示す。
