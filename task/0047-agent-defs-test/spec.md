# エージェント定義の規約をテストで恒久化する

`.claude/agents/` のエージェント定義に入れた規約が、後の編集で黙って消えないよう CI で強制する。

## 種別

改善

## 対象

- 場所: `tests/agent-defs.test.mjs`（新設）、検証対象は `.claude/agents/*.md`
- 公開面: `npm run ci` が回すユニットテストに 1 ファイル増える

## 背景

0036 は `.claude/agents/codex-reviewer.md` に「サンドボックス内でテストを再実行しない」「実測 CI 結果が無ければ承認しない」という規約を入れた。完了条件 5・6 はこの 2 つの記述が存在することを求めており、検証は `grep` の出力を会話に貼ることで行った。

**その検証は 1 回きりである。** アーカイブした後にこの節が消されても、`npm run ci` は何も言わない。エージェント定義は `tests/` の保護対象でもないため、凍結ガードも反応しない。

同じことが今後入る規約すべてに当てはまる。規約をエージェント定義に書く方式を採る以上、その存在を CI で恒久的に確かめる仕組みが要る。

`tools/check-protected-paths.mjs` のテストが示すとおり、`tests/` への**新規追加**は凍結違反にならない（既存テストの期待値変更・削除が違反である）。したがってこの作業は凍結手続きを踏まずに実施できる。

## 仕様

`.claude/agents/codex-reviewer.md` が満たすべき命題を、`tests/agent-defs.test.mjs` だけで恒久検証する。既存の `tests/` と `.claude/agents/*.md` の中身は変えない。

検証の粒度（昇格時に確定）:

- **ファイル全体の文字列一致は使わない。** 文言の微修正で壊れるため。
- **実質を確かめる。** 少なくとも次の 3 点。
  1. サンドボックス内での `npm run ci`・ユニットテスト・e2e の再実行を禁じる節がある。現行の見出しは「テスト結果の扱い」。見出し文言の微修正は通してよいが、再実行禁止の事実を持つ節が消えたら失敗する。
  2. 親が実測の CI 結果を会話に貼っていないときは承認しない、という規則がある。
  3. 出力スキーマの必須 4 項目名が**この順番**で定義されている: `severity`、`根拠`、`完了条件番号`、`一文の要約`。
- 事実が残る文言の微修正ではテストは通る。該当節の削除、または必須 4 項目名の欠落・順番入れ替えでは失敗する。
- `codex-reviewer.md` が存在しないときは黙ってスキップせず失敗する。
- 判定は本文を受け取る純関数（または同等）として書き、欠落・削除ケースをリポジトリの実ファイルを消さずに示せるようにする。

公開面: 新ファイルは `tools/run-unit-tests.mjs` の `listUnitTestFiles`（`tests/*.test.mjs` から `calc-page.test.mjs` を除く列挙）に自動で入る。runner は変更しない。

## 範囲外

- 既存 `tests/` の変更（凍結対象）
- エージェント定義の内容そのものの変更
- `.claude/skills/` の検証
- 凍結リスト（`GATE_HELPERS`・`loop.manifest.json` の `protectedPaths` など）の変更
- `tools/run-unit-tests.mjs` の変更（凍結対象。新ファイルは自動列挙される）

## 失敗時

- 対象のエージェント定義（`codex-reviewer.md`）が存在しない: テストは失敗する（黙ってスキップしない）
- 再実行禁止の事実を持つ節（現行は「テスト結果の扱い」）が消えている: テストは失敗する
- 親が実測 CI 結果を渡していないときの非承認ルールが消えている: テストは失敗する
- 出力スキーマの必須 4 項目名（`severity`、`根拠`、`完了条件番号`、`一文の要約`）が欠けている、またはこの順番でない: テストは失敗する

## 例

検証に使う具体例。欠落・削除はリポジトリの実ファイルを消さず、純関数（または同等）へ本文を渡して示す。

| 操作または入力 | 期待結果 |
|---|---|
| `tests/agent-defs.test.mjs` を置いて `npm run ci`（または `node --test tests/agent-defs.test.mjs`） | 現状の `.claude/agents/codex-reviewer.md` で pass。`tools/run-unit-tests.mjs` は変更しない |
| テストが読むパスに `codex-reviewer.md` が無い | fail（skip しない） |
| 「テスト結果の扱い」相当の節を残し、再実行禁止と実測なし非承認の事実が残る文言に微修正した本文 | pass |
| 再実行禁止の節を削除した本文 | fail |
| 必須 4 項目名をこの順（`severity` → `根拠` → `完了条件番号` → `一文の要約`）で含む本文 | pass |
| 4 項目名のうち 1 つを欠いた本文 | fail |
| 4 項目名の順番を入れ替えた本文 | fail |

## 完了条件

次をすべて満たしたとき、この仕様は完了とする。検証はこれらの条件に対して行い、テスト実行結果などのコマンド出力を根拠にする。

1. 「対象」が仕様どおりに公開または修正されている。
2. 「例」がすべて、テストまたは再現手順で同じ結果になる。
3. 「失敗時」に書いた入力・操作で、仕様どおり失敗する。該当がなければこの項は「なし」。
4. 「範囲外」を実装していない。
5. `tests/agent-defs.test.mjs` が新設され、`npm run ci`（`tools/run-unit-tests.mjs` の `listUnitTestFiles` 経由）で実行される。runner と既存の `tests/*.test.mjs` は変更していない（`git diff` で新ファイル以外が `tests/` に無いことで示す）。
6. `.claude/agents/*.md` の内容は変更していない（`git diff` で当該パスに差分が無いことで示す）。
7. `codex-reviewer.md` が無いとき、テストは黙ってスキップせず失敗する。「例」の欠落行の実行結果を根拠にする。
8. テストはファイル全体の文字列一致ではなく、次の実質を確かめる。(a) サンドボックス内での `npm run ci`・ユニットテスト・e2e 再実行を禁じる節（現行見出し「テスト結果の扱い」）。(b) 親が実測 CI 結果を貼っていないときは承認しない規則。(c) 出力スキーマの必須 4 項目名がこの順: `severity`、`根拠`、`完了条件番号`、`一文の要約`。
9. 事実が残る文言の微修正ではテストは通る。該当節の削除、または必須 4 項目名の欠落・順番入れ替えでは失敗する。「例」の各行の実行結果を根拠にする。
