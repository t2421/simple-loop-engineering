# worktree による並列作業の導入

独立した 2 作業を別々の git worktree で並列に進め、その運用規約を CLAUDE.md に定める。

## 種別

その他（プロセス演習 + 規約追加）

## 対象

- 場所: `CLAUDE.md`（worktree 運用の節を追加）、`.worktrees/`（worktree の置き場。gitignore する）
- 公開面: なし

## 背景

これまでの作業はすべて単一チェックアウト・単一ブランチの直列実行で、Loop Engineering の Worktrees 要素（並列エージェントのファイル衝突防止）が未体験。並列時に progress の更新やアーカイブがどう競合するかも未定義。

## 仕様

- CLAUDE.md に worktree 運用の節を追加する。最低限次を含む:
  - worktree は `.worktrees/<ブランチ名>` に作る
  - 1 worktree = 1 作業 = 1 ブランチ。progress の更新は各自のブランチで行う
  - `progress/` や `CLAUDE.md` の競合は PR のマージ順に解決する。アーカイブはマージされた側から順に行う
- 演習として、互いに独立した小さい作業 2 本（例: `math-mul` と `math-div`。着手時に `specs/TEMPLATE.md` から spec 化する）を、それぞれ別 worktree・別ブランチで並列に実施し、別々の PR を作る
- 各作業の進捗の試行ログに、使用した worktree のパスとブランチを記録する

## 範囲外

- 3 本以上の並列
- worktree の作成・削除の自動化（スクリプト化）
- 並列作業間で依存がある場合の運用

## 失敗時

なし。

## 例

| 操作または入力 | 期待結果 |
|---|---|
| `git worktree list` | 並列実施中、`.worktrees/` 配下に 2 つの worktree が表示される |
| 各 worktree で `npm run ci` | 互いに影響せず、それぞれ独立に成功する |
| 演習 2 作業の PR | 別ブランチから 2 本作成されている |

## 完了条件

次をすべて満たしたとき、この仕様は完了とする。検証はこれらの条件に対して行い、テスト実行結果などのコマンド出力を根拠にする。

1. 「対象」が仕様どおりに公開または修正されている。
2. 「例」がすべて、テストまたは再現手順で同じ結果になる。
3. 「失敗時」に書いた入力・操作で、仕様どおり失敗する。該当がなければこの項は「なし」。
4. 「範囲外」を実装していない。
5. CLAUDE.md に worktree 運用の節がある。演習 2 作業の PR が別 worktree から作られ、両作業の進捗の試行ログに worktree パスとブランチが記録されている（`git worktree list` の出力を会話に貼る）。
