# 作業開始を 1 コマンドにする `tools/start-task.mjs`

タスク選択・ID 採番・worktree 作成を 1 コマンドで行う `tools/start-task.mjs` を追加する。

## 種別

機能追加

## 対象

- 場所: `tools/start-task.mjs`、`tests/start-task.test.mjs`、`CLAUDE.md`（「開発ループ」の Plan、作業の識別子の記述、「並列作業（worktree）」の作成手順)
- 公開面: `node tools/start-task.mjs [--next-id]`

## 背景

作業開始は「タスクを選ぶ → ブランチ名を決める → `git worktree add` → `npm ci`」という暗黙の複数手順であり、エージェントが worktree の作成を飛ばしてプライマリチェックアウトで実装を始めるケースが頻発している。またタスク選択に順序規則がなく、セッションごとに選ぶ作業がぶれる。ID の採番は CLAUDE.md のハードコード（「いまは 0016」）に頼っており、実際は 0019 まで使用済みで既に陳腐化している。

手順が複数である限り一部の省略が起こる。開始を 1 コマンドに畳み、選択と採番を計算に置き換える。

## 仕様

引数なしで実行したとき:

- `task/` の `archive/` 以外の各 `NNNN-slug/progress.md` を読み、**Status** が `Blocked` と `Done` のどちらでもない作業のうち**最小 ID** を選ぶ
- 選んだ progress の **Branch** を読み、`.worktrees/<ブランチ名>` が無ければ `git worktree add .worktrees/<ブランチ名> -b <ブランチ名> main` で作成し、その中で `npm ci` を実行する
- `.worktrees/<ブランチ名>` が既に存在するなら作成と `npm ci` をスキップする（再入可能）
- 選んだ作業の ID・slug と worktree の絶対パスを標準出力に出す

`--next-id` で実行したとき:

- `task/`（`archive/` を含む）と `backlog/` の `NNNN-slug` 形式ディレクトリの最大 ID + 1 を、ゼロ埋め 4 桁で標準出力に出す

CLAUDE.md の追随:

- 「開発ループ」の Plan を「`node tools/start-task.mjs` を実行し、出力された作業と worktree で開始する」に書き換える
- 採番の記述を「`node tools/start-task.mjs --next-id` で計算する」にし、ハードコードされた現在番号を削除する
- 「並列作業（worktree）」の作成コマンド例を本ツールへの参照に置き換える

## 範囲外

- worktree の削除・片付け（現状どおり手動）
- プライマリチェックアウトでの実装編集のブロック（`0021-loop-hooks` の範囲）
- 複雑度によるモデルルーティングの出力（`0025-model-routing` の範囲）
- 選択の対話的な上書き（特定 ID を指定して開始する機能）

## 失敗時

- 選択可能な作業が無い（すべて Blocked / Done、または作業ディレクトリが無い）: 何も作成せず、その旨を出力して非 0 で終了する
- 選んだ progress に **Branch** が無い、またはブランチ名として不正: 何も作成せず非 0 で終了する
- `git worktree add` が失敗: 非 0 で終了する。部分状態を残さない
- `npm ci` が失敗: worktree は残したまま非 0 で終了する（再実行で再入する）

## 例

| 操作または入力 | 期待結果 |
|---|---|
| `task/0020-a/`（Not Started）と `task/0021-b/`（In Progress）がある状態で引数なし実行 | `0020-a` が選ばれ、その Branch の worktree が作成され、パスが出力される |
| 最小 ID の作業が `Blocked` の状態で引数なし実行 | 次に小さい ID の作業が選ばれる |
| 選ばれた作業の worktree が既にある状態で引数なし実行 | 作成をスキップし、既存パスを出力して 0 で終了する |
| すべての作業が `Blocked` の状態で引数なし実行 | 何も作成せず非 0 で終了する |
| `task/archive/` の最大が `0019`、`backlog/` の最大が `0015` の状態で `--next-id` | `0020` |

## 完了条件

次をすべて満たしたとき、この仕様は完了とする。検証はこれらの条件に対して行い、テスト実行結果などのコマンド出力を根拠にする。

1. 「対象」が仕様どおりに公開または修正されている。
2. 「例」がすべて、テストまたは再現手順で同じ結果になる。
3. 「失敗時」に書いた入力・操作で、仕様どおり失敗する。該当がなければこの項は「なし」。
4. 「範囲外」を実装していない。
5. 「例」の各行が `tests/start-task.test.mjs` のユニットテスト（一時ディレクトリ上の git リポジトリで、`npm ci` は注入で差し替え）で網羅されている。CLAUDE.md から採番のハードコードが消えている。
