# codex サンドボックス内 CI 実行のノイズ排除

`codex-reviewer` が read-only サンドボックス内で `npm run ci` を回して環境要因の失敗を毎回釈明する無駄を無くす。

## 種別

改善

## 対象

- 場所: `.claude/agents/codex-reviewer.md`
- 公開面: Verify (外部) のレビュー実行手順

## 背景

`codex-reviewer` が read-only サンドボックスで `npm run ci` を実行すると、`mkdtemp` を使うテストが 90 件失敗する（`EPERM: operation not permitted, mkdtemp '/var/folders/.../T/...'`）。実装の欠陥ではなく環境要因だが、レビュアーが毎回それを切り分けて釈明する必要があり、出力とトークンを無駄にしている。

2026-08-22 のセッションで `0030` と `0033` の両方のレビューで発生し、いずれもレビュアーが「サンドボックス起因であり欠陥ではない」と釈明していた。サンドボックス外では 360〜390 件すべて pass する。

対処の候補は 3 つあった。

- (a) エージェント定義に「サンドボックス内で `npm run ci` を回さない。親が実測結果を渡す」と書く
- (b) テスト側が書き込み可能な一時ディレクトリを選べるようにする（ただし `tests/` は凍結対象）
- (c) レビュー依頼時に実測結果を必ず添える運用にする（現状すでにそうしているが、それでもレビュアーが自分で回している）

昇格にあたり **(a) を採る**と決めた。(b) は `tests/` の変更で凍結対象に触れるため範囲外。(c) は既に運用しているが効いていない（レビュアーが自分で回してしまう）。

`0026-review-output-schema` と関連していたが、2026-08-23 のリファインメントで確認したとおり、0026 は PR #57 でマージされ `task/archive/0026-review-output-schema/` にアーカイブ済みである。変更後の `.claude/agents/codex-reviewer.md` には出力スキーマ・Critical の条件・承認規則が入ったが、サンドボックス内で `npm run ci` を回すことへの言及は無い。着手を妨げる依存は無い。

## 仕様

`.claude/agents/codex-reviewer.md` に次の規約を追記する。

- サンドボックス内で `npm run ci`・ユニットテスト・e2e を再実行しない。read-only サンドボックスでは `mkdtemp` を使うテストが環境要因で失敗し、その釈明はノイズだからである
- テストの合否は、親（依頼側）が会話に貼った実測の CI 結果を判定材料にする
- 親が実測の CI 結果を渡していないときは承認せず、実測結果の提示を求める

既存の手順（`codex review --uncommitted` の実行、出力スキーマ、Critical の条件、承認規則）は変えない。

## 範囲外

- `tests/` 配下のテストコードの変更（凍結対象。候補 (b) を採るなら凍結解除の手続きが要る）
- サンドボックスの権限設定そのものの変更
- `.claude/agents/codex-reviewer.md` の既存節（出力スキーマ・Critical の条件・承認規則）の変更

## 失敗時

- 親が実測 CI 結果を渡さずにレビューを依頼した: レビュアーは承認せず、実測結果の提示を求める

## 例

検証に使う具体例。1〜2 行目は定義ファイルの内容で機械的に確認する。3〜4 行目はエージェントの振る舞いのため非決定的であり、再現手順としての補助的な確認とする。

| 操作または入力 | 期待結果 |
|---|---|
| `grep -n "npm run ci" .claude/agents/codex-reviewer.md` | サンドボックス内で再実行しない旨の規約の行が表示される |
| `grep -n "実測" .claude/agents/codex-reviewer.md` | 親の実測 CI 結果を判定材料にする旨と、無ければ承認しない旨の行が表示される |
| レビュー依頼（実測 CI 結果添付あり） | サンドボックス失敗（`mkdtemp` / `EPERM`）の釈明を含まないレビュー結果が返る |
| レビュー依頼（実測 CI 結果添付なし） | 承認されず、実測結果の提示を求められる |

## 完了条件

次をすべて満たしたとき、この仕様は完了とする。検証はこれらの条件に対して行い、テスト実行結果などのコマンド出力を根拠にする。

1. 「対象」が仕様どおりに公開または修正されている。
2. 「例」がすべて、テストまたは再現手順で同じ結果になる。
3. 「失敗時」に書いた入力・操作で、仕様どおり失敗する。該当がなければこの項は「なし」。
4. 「範囲外」を実装していない。
5. `.claude/agents/codex-reviewer.md` に「サンドボックス内で `npm run ci`（ユニットテスト・e2e を含む）を再実行しない」旨の規約が書かれており、`grep -n` の出力で該当行を提示できる。
6. `.claude/agents/codex-reviewer.md` に「テストの合否は親が渡した実測の CI 結果を判定材料にする。実測結果が渡されていないときは承認せず、提示を求める」旨の規約が書かれており、`grep -n` の出力で該当行を提示できる。
7. 「例」の 3〜4 行目の振る舞いを、レビュー依頼各 1 回の再現手順で確認する（補助的な確認。エージェントの振る舞いは非決定的なため、主たる判定は 5・6 の定義内容で行う）。
