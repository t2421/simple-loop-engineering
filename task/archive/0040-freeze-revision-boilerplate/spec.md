# 凍結改訂の標準完了条件を定型化する

凍結対象に触れる作業の spec に毎回手書きしている定型（改訂理由の明記、ラベル無しで `protected-paths` が失敗しラベル付きで成功する確認）を、書き写しではなく参照できる形にする。

## 種別

改善

## 対象

- 場所: `.claude/agents/spec-author.md`。規約に「凍結改訂の標準完了条件」の節を足す。このファイルは凍結対象ではないため、**この作業自体は凍結対象に触れない**。`allow-protected-change` ラベルは不要である
- 公開面: なし（起草時の規約）

## 背景

2026-08-22 のリファインメントで昇格した 0027（`tools/check-protected-paths.mjs`）と 0034（`.github/workflows/preview.yml`）はどちらも凍結改訂で、次の定型を両方の spec に同文で手書きした。

- 背景に「凍結改訂である」宣言と、なぜ検証を弱めないかの理由
- 失敗時に「ラベル無しの PR は `protected-paths` が検知して失敗する（正しい挙動）」
- 完了条件に「ラベル無しで失敗し、`allow-protected-change` ラベル付きの再実行で成功する」

依頼側もこの定型を毎回プロンプトで指示しており、書き漏れ・表現の揺れの温床になっている。定位置を 1 つ決めて参照させれば、spec ごとの書き写しが「参照 + 作業固有の理由 1 行」に縮む。

2026-08-23 のリファインメントで現存を実測確認した（`.claude/agents/spec-author.md` に
`allow-protected-change` への言及は 0 件）。

置き場所は候補が 2 つあった。(a) `.claude/agents/spec-author.md` の規約（凍結対象ではない）。(b) `task/TEMPLATE-spec.md`（**凍結対象**。改訂には `allow-protected-change` ラベルと人間のマージが要る）。昇格時に (a) を採った。テンプレート自体を触らずに同じ効果が得られ、改訂手続きが軽いためである。

## 仕様

- `.claude/agents/spec-author.md` に「凍結改訂の標準完了条件」の規約を 1 箇所定義する。次の 4 点を標準要件として明記する
  1. **宣言**: spec の「背景」に、凍結改訂であることを宣言する
  2. **理由**: 「背景」に、なぜこの変更が検証を弱めないかの理由を書く
  3. **ラベル運用**: 「失敗時」に「`allow-protected-change` ラベル無しの PR は `protected-paths` が検知して失敗する（正しい挙動）」を書く
  4. **標準完了条件の文**: 「完了条件」に「ラベル無しで `protected-paths` が失敗し、`allow-protected-change` ラベル付きの再実行で成功する」を書く
- spec-author は、起草する spec の対象が凍結対象（`tools/check-protected-paths.mjs` の保護対象）に触れるとき、依頼文に指示が無くてもこの 4 点を spec に織り込む
- 作業固有に書くのは「なぜこの変更が検証を弱めないか」の理由だけ

## 範囲外

- 凍結対象リスト自体の増減（それは `.claude/skills/add-protected-path`）
- ガード（`tools/check-protected-paths.mjs`）の変更
- `task/TEMPLATE-spec.md` の変更（凍結対象。この作業では触れない）

## 失敗時

なし（起草規約であり、実行時の失敗分岐はない）。

## 例

| 操作または入力 | 期待結果 |
|---|---|
| 凍結対象に触れる意図で spec-author に起草を依頼する | 依頼文に指示が無くても、宣言・理由・ラベル運用・標準完了条件が spec に入る |

## 完了条件

次をすべて満たしたとき、この仕様は完了とする。検証はこれらの条件に対して行い、テスト実行結果などのコマンド出力を根拠にする。

1. 「対象」が仕様どおりに公開または修正されている。
2. 「例」がすべて、テストまたは再現手順で同じ結果になる。
3. 「失敗時」に書いた入力・操作で、仕様どおり失敗する。該当がなければこの項は「なし」。
4. 「範囲外」を実装していない。
5. `.claude/agents/spec-author.md` に「凍結改訂の標準完了条件」を定義する節が存在し、次の 4 点がすべて明記されている。検証は該当行の `grep` 出力を根拠にする。
   - 宣言: 「背景」に凍結改訂であることを宣言する要件
   - 理由: 「背景」に、この変更が検証を弱めない理由を書く要件
   - ラベル運用: 「失敗時」に、ラベル無しの PR は `protected-paths` が検知して失敗する（正しい挙動）と書く要件
   - 標準完了条件の文: 「完了条件」に、ラベル無しで `protected-paths` が失敗し `allow-protected-change` ラベル付きの再実行で成功する、という命題を入れる要件
6. `.claude/agents/spec-author.md` に、対象が凍結対象のとき依頼文に指示が無くても上記 4 点を織り込む旨の指示がある。`grep -c 'allow-protected-change' .claude/agents/spec-author.md` が 1 以上を返す。
7. この作業の差分に凍結対象（`tools/check-protected-paths.mjs` の保護リスト該当パス）が含まれない。PR の `protected-paths` チェックがラベル無しで成功する。
