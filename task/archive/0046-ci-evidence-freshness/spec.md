# 実測 CI 結果の鮮度

レビュー依頼に添える実測 CI 結果が、レビュー対象の差分が確定した後に取得されたものであることを要求する。

## 種別

改善

## 対象

- 場所: `CLAUDE.md`「トークンコスト」節、`.claude/agents/codex-reviewer.md`「テスト結果の扱い」節
- 公開面: レビュー依頼に添える実測 CI 結果の要件

## 背景

0036 で「レビュアーはサンドボックス内でテストを再実行しない。合否は親が渡した実測の CI 結果で判定する」という規約を入れた。これは read-only サンドボックスでの `EPERM` ノイズを排除するための対処で、目的は果たしている。

しかし現在の規約は**実測結果の存在しか求めていない。それがいつ取得されたものかを問わない。**

したがって次の経路が通る。

1. 実装する
2. `npm run ci` を回す。緑になる
3. さらに実装を足す（あるいは指摘を受けて直す）
4. 2 の緑をそのまま貼ってレビューを依頼する
5. レビュアーは規約どおり自分では回さないので、古い緑を根拠に承認する

**再実行しないという規約が、古い結果を無条件に信じる規約に化ける。** 0036 の対処は必要だったが、その副作用としてこの穴が開いた。

これは検証を弱める方向の穴なので、塞ぐ側の作業である。

0047（アーカイブ済み）が `tests/agent-defs.test.mjs` で、同ファイルのサンドボックス再実行禁止・実測 CI 必須・出力スキーマ 4 項目の順を恒久検証している。この作業は鮮度の要件を足すが、その 3 事実は残す。サンドボックス内でテストを再実行する形へ差し戻さない。

## 仕様

実測 CI 結果には、それがレビュー対象の差分に対応していることを示す情報を添える。

- 実測結果を取得した時点のリビジョン（コミット SHA）が、レビュー対象の差分の HEAD と一致すること
- 未コミットの変更がある状態で取得した結果は、その旨が分かること
- 対応が確認できないとき、レビュアーは承認しない。取り直しを求める

判定の置き場所（昇格時に確定）:

- **主は規約の文言。** `CLAUDE.md`「トークンコスト」と `.claude/agents/codex-reviewer.md`「テスト結果の扱い」に、上の 3 点を書く。文言は微修正してよいが、事実は残す
- **機械的チェックは任意。** 置くなら新規の `tests/*.test.mjs` だけにする。判定は本文を受け取る純関数（または同等）とし、ファイル全体の文字列一致は使わない。既存の `tests/agent-defs.test.mjs` は変更しない（凍結対象。0047 の 3 事実を弱めない）
- 0047 が固定した次の 3 事実は残す（「テスト結果の扱い」の文言を足してよいが、事実を消してはいけない）:
  1. サンドボックス内での `npm run ci`・ユニットテスト・e2e 再実行を禁じる
  2. 親が実測の CI 結果を渡していないときは承認しない
  3. 出力スキーマの必須 4 項目名がこの順: `severity`、`根拠`、`完了条件番号`、`一文の要約`

## 範囲外

- サンドボックス内でテストを再実行する形への差し戻し（0036 / 0047 の対処を無効化しない）
- CI そのものの高速化
- レビュー往復上限（5 回）の変更
- 既存 `tests/` の変更（`tests/agent-defs.test.mjs` を含む。凍結対象）
- `.claude/agents/` のうち `codex-reviewer.md` 以外（`grok-reviewer.md` など）
- 出力スキーマの項目名・順番の変更
- 0047 が固定した再実行禁止・実測 CI 必須の削除または骨抜き

## 失敗時

- 実測 CI 結果に取得時点のリビジョン（コミット SHA）が添えられていない: 承認せず、取り直しを求める
- 添えられたリビジョンがレビュー対象の差分の HEAD と一致しない: 承認せず、取り直しを求める
- 未コミットの変更がある状態で取得したのに、その旨が無い: 承認せず、取り直しを求める
- 実測結果とレビュー対象 HEAD の対応が確認できない（曖昧・欠落）: 承認せず、取り直しを求める

## 例

検証に使う具体例。1〜4 行目は定義ファイルの内容で機械的に確認する。5〜8 行目はエージェントの振る舞いのため非決定的であり、再現手順としての補助的な確認とする。

| 操作または入力 | 期待結果 |
|---|---|
| `grep -n "HEAD" CLAUDE.md`（「トークンコスト」節） | 実測 CI の取得リビジョンがレビュー対象 HEAD と一致することを求める行がある |
| `grep -n -e HEAD -e リビジョン -e 未コミット .claude/agents/codex-reviewer.md`（「テスト結果の扱い」節） | 取得 SHA がレビュー対象 HEAD と一致すること、未コミット付き取得はその旨が分かること、一致が確認できないときは承認しないことが書いてある |
| `grep -n "再実行しない" CLAUDE.md .claude/agents/codex-reviewer.md` | サンドボックス内での再実行禁止が両方に残っている |
| `node --test tests/agent-defs.test.mjs` | pass（0047 の 3 事実: サンドボックス再実行禁止、実測 CI 必須、スキーマ 4 項目の順が残る） |
| レビュー依頼。実測 CI の SHA がレビュー対象 HEAD と一致し、未コミットが無い（または有ることが明記されている） | 鮮度を理由に拒否しない（他の承認条件は別） |
| レビュー依頼。実測 CI に SHA が無い | 承認しない。取り直しを求める |
| レビュー依頼。実測 CI の SHA がレビュー対象 HEAD と一致しない（実装を足したあとの古い緑） | 承認しない。取り直しを求める |
| レビュー依頼。未コミットがある状態で取得したのにその旨が無い | 承認しない。取り直しを求める |

## 完了条件

次をすべて満たしたとき、この仕様は完了とする。検証はこれらの条件に対して行い、テスト実行結果などのコマンド出力を根拠にする。

1. 「対象」が仕様どおりに公開または修正されている。
2. 「例」がすべて、テストまたは再現手順で同じ結果になる。
3. 「失敗時」に書いた入力・操作で、仕様どおり失敗する。該当がなければこの項は「なし」。
4. 「範囲外」を実装していない。
5. `CLAUDE.md`「トークンコスト」に、実測 CI 結果を取得したコミット SHA がレビュー対象の差分の HEAD と一致すること、未コミットがある状態で取得したらその旨を添えること、一致が確認できないときは承認しないことが書いてある。`grep` の出力で該当行を提示できる。
6. `.claude/agents/codex-reviewer.md`「テスト結果の扱い」に、5 と同じ 3 事実がある。サンドボックス内での `npm run ci`・ユニットテスト・e2e 再実行禁止は残っている。`grep` の出力で該当行を提示できる。
7. 出力スキーマの必須 4 項目名と順番（`severity` → `根拠` → `完了条件番号` → `一文の要約`）を変えていない。親が実測 CI を渡していないときは承認しない、の事実も残っている。`node --test tests/agent-defs.test.mjs` が pass することで検証する。
8. 実装差分は `CLAUDE.md`「トークンコスト」と `.claude/agents/codex-reviewer.md`「テスト結果の扱い」（と、置くなら新規の `tests/*.test.mjs`）に限る。既存 `tests/`・`loop-core/`・`package.json`・凍結リストを変えていないことを `git diff main --stat` で示す。
