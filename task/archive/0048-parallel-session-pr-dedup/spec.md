# 並行セッションによる派生 PR の重複

同じ問題から派生した docs PR が、並行して動くセッションから二重に作られるのを防ぐ手順を `CLAUDE.md` に足す。

## 種別

改善

## 対象

- 場所: `CLAUDE.md`「並列作業（worktree）」節と「コミットとマージ」節
- 公開面: 並行作業を進めるとき、および派生 docs PR を開くときに守る手順
- `CLAUDE.md` は凍結対象ではない（`loop-core/templates/CLAUDE.md` とは別ファイル）。`allow-protected-change` ラベルは不要

## 背景

`CLAUDE.md` の並列作業の規約は「触るファイルが重ならない作業どうしを選べば衝突しない」を前提に、**ディレクトリの割当**までを扱っている。`0039-parallel-docs-rules` もこの前提の上にある。

2026-08-24 に、この前提が成り立たない実例が出た。

`0036` の Verify (外部) で `CLAUDE.md` との規約衝突が見つかり、その対処として `CLAUDE.md`「トークンコスト」節を改訂する docs PR が必要になった。このとき**2 つのセッションが独立に同じ診断へ到達し、同じ改訂の PR を 2 本作成した。**

| PR | ブランチ | 結果 |
|---|---|---|
| #62 | `docs/review-input-contract` | 重複として close |
| #63 | `docs/review-request-ci-evidence` | マージ |

差分の 1 行目は完全に同一、2 行目は文言のみ相違だった。

重複した理由は担当ディレクトリの取り合いではない。**別々の作業をしていた 2 つのセッションが、同じ 1 つの発見から同じ派生作業を導いた**ことによる。派生 PR は着手前に予測できないため、事前のディレクトリ割当では防げない。

現状の実害は、レビューと判断の二重コストと、どちらを残すかの調整である。

手段は手順の規約だけとする。セッション間の実行時ロック・排他制御は入れない。機械的な検知（ブランチ名の必須規約、PR 本文への由来 ID 必須、bot の自動 close）もこの作業では入れない（範囲外に明記する）。

**この作業自体が同じ問題を踏みうる**（並行セッションが同時にこの規約を書きに来る）。着手は他セッションが動いていない時点を選ぶ。

## 仕様

`CLAUDE.md` の「並列作業（worktree）」節と「コミットとマージ」節に、派生 docs PR の重複を防ぐ手順を足す。手段は手順の規約だけで、実行時の仕組みは入れない。

- **作成前の確認**: 派生 docs PR を新規に開く直前に、オープンな PR を確認する。確認する材料はタイトル・本文・ブランチ名・変更対象である
- **同じ意図の定義**: 直そうとしている対象（同じファイルの同じ節、または同じ発見から導いた同じ種類の docs 改訂）が一致すること。文言が違っても対象と種類が同じなら同じ意図である
- **合流**: 同じ意図のオープン PR が既にあれば、新規に作らない。既存 PR にコメントして合流する（必要ならそのブランチに差分を足す）
- **畳み方（人間の指定が無いとき）**: 残すのは先にオープンされた PR。後から作った側が自分の PR を close し、残す PR へのリンクと重複である旨をコメントする。後発にだけある有意な差分は close 前に残す側へ取り込む
- **人間の指定が優先**: 人間が残す側を明示したらそれに従う（実例: #62 を close し #63 をマージ）
- この変更は `CLAUDE.md` へのルール変更なので、「コミットとマージ」の規約どおり独立した docs PR で main へ入れる。進行中の作業ブランチに混ぜない

## 範囲外

- セッション間の実行時ロックや排他制御の仕組み
- 機械的な検知（ブランチ名の必須規約、PR 本文への由来 ID の必須記載、bot による自動 close）
- `0039-parallel-docs-rules` が扱うディレクトリ割当そのもの
- 実装 PR（`task/` の作業ブランチ）の重複

## 失敗時

規約違反として扱う条件。実行時のエラー分岐ではない。

- `確認せずに派生 docs PR を新規作成した`: 規約違反。オープン PR の確認は作成前の必須手順
- `同じ意図のオープン PR があるのに新規作成した`: 規約違反。既存 PR へ合流する
- `重複を検知したのに、人間の指定なく両方残した`: 規約違反。畳み方の規準（先発を残し、後発を close してコメント）に従う
- `違う意図の PR を誤って畳んだ`: 規約違反。同じ意図の定義（対象と種類の一致）に照らして判断する

## 例

| 操作または入力 | 期待結果 |
|---|---|
| `grep -n "派生" CLAUDE.md` | 「並列作業（worktree）」節または「コミットとマージ」節の行に、派生 docs PR の作成前確認・合流・畳み方の手順がヒットする |
| 派生 docs PR を開く直前に、同じ意図のオープン PR（同じ `CLAUDE.md` の同じ節を直す PR）を見つけた | 新規 PR を作らない。既存 PR にコメントして合流する。必要ならそのブランチに差分を足す |
| 派生 docs PR を作った後で、先にオープンされていた同じ意図の PR に気づいた（人間の指定なし） | 後発の自分の PR を close し、先発 PR へのリンクと重複である旨をコメントする。後発にだけある有意な差分は close 前に先発側へ取り込む |
| 重複した 2 本のうち、人間が「#62 を close、#63 をマージ」と指定した | 指定に従う。先発・後発の規準より人間の指定が優先する |

## 完了条件

次をすべて満たしたとき、この仕様は完了とする。検証はこれらの条件に対して行い、テスト実行結果などのコマンド出力を根拠にする。

1. 「対象」が仕様どおりに公開または修正されている。
2. 「例」がすべて、テストまたは再現手順で同じ結果になる。
3. 「失敗時」に書いた入力・操作で、仕様どおり失敗する。該当がなければこの項は「なし」。
4. 「範囲外」を実装していない。
5. `CLAUDE.md` の「並列作業（worktree）」節と「コミットとマージ」節に、派生 docs PR を新規に開く直前にオープンな PR（タイトル・本文・ブランチ名・変更対象）を確認する手順がある。`grep` の出力で確認する。
6. 同じ意図の定義（直す対象と改訂の種類が一致すれば、文言が違っても同じ意図）と、同じ意図のオープン PR が既にあれば新規に作らず既存へ合流する旨が、当該節に明記されている。
7. 重複時の畳み方の規準が当該節に明記されている: 人間の指定が無ければ先にオープンされた PR を残す。後発の側が自分の PR を close し、残す PR へのリンクと重複である旨をコメントする。後発にだけある有意な差分は close 前に残す側へ取り込む。人間が残す側を明示したらそれに従う。
8. 「範囲外」の項目（セッション間ロック、機械的検知、0039 のディレクトリ割当の変更、実装 PR の重複対応）を実装していない。`git diff` に該当する変更が無いことで確認する。
9. 実装 PR の差分が `CLAUDE.md` の当該節と `task/0048-parallel-session-pr-dedup/progress.md` の更新だけである。`git diff --stat` で確認する。
